## 보존한 내용

최초 복원인 `classic-v1`은 상수까지 원작을 따랐다. 현재도 이벤트 순서, 매초의 계단식 감쇠, 입력 때만 갱신되는 흰 덮개, 앞 글자가 제거되는 문장, 실제 불투명 마킹, 지문 완료 조건을 보존한다. 오타 삭제도 원작처럼 오답 변경으로 판정한다. 고속 오타의 첫 이벤트에서 덮개가 옅어질 수 있는 순서를 유지했다.

최초 복원에서는 원작 영문 30개를 사용했다. 이후 사용자의 지문 교체·확대 요청에 따라 한글 30개와 영문 30개의 현대적인 창작 지문으로 교체했다. 판정 규칙은 그대로다. 이전 지문과 비교하면 한 판의 길이와 얻을 수 있는 총점은 달라진다. 기록에는 지문 제목이 남는다.

## 기술적 수정과 표시 차이

- 동일 밀리초 입력 간격은 최소 1ms로 처리하여 Infinity를 방지한다.
- 문자열 범위를 검사하고 확정된 NFC 한 글자만 평가한다. 붙여넣기/일괄 입력은 제한한다. UTF-16 절단 대신 Unicode code point를 사용한다.
- IME 조합 중에는 평가하지 않으며 후속 중복 콜백을 억제한다.
- 재시작 때 직전 정답 시간과 타이머를 초기화하고 컴포넌트 종료 시 타이머를 정리한다. 원본의 재시작 후 오래된 시간값/타이머 누수는 복제하지 않는다.
- 원작의 페이지 전체 확대 지문·랜덤 색상 배경은 집중을 위해 생략했다. HTML 글꼴 메트릭은 Flutter와 완전히 같지 않다.
- 별도 입력창 대신 원문 위의 투명 입력 요소를 사용한다. 다음 글자에 선명도 예외를 주지 않는다.

## 사용자 요청에 따른 성장 완화 (`classic-v2`)

초기부터 너무 넓게 가려지고 지나치게 빨리 자란다는 피드백에 따라 성장 상수를 조정했다. 첫 5정답은 1px, 이후 10정답은 점진적 성장이다. 기본 증가량은 `min(CPM, 900)/250`, 내부 너비 상한은 80(표시 120px)이다. 기존의 상한 초과를 허용하는 방식은 폐기했다. 선명도 회복은 내부 정수 너비 12 초과에서 시작한다. 낮아진 성장량과 기존의 정수 감쇠를 함께 고려한 기준이며, 300 CPM으로 꾸준히 입력할 때 선명도가 회복되는 것을 검사한다.

추가 피드백에 따라 분모를 300에서 250으로 바꿔 직전 조정 대비 성장량을 20% 높였다. 준비 구간, 감쇠, 선명도 기준과 최대 길이는 유지했다. 입력 간격이 같은 밀리초로 몰려도 입력당 내부 증가량은 3.6 이하이다. `classic-v1` 기록은 삭제하지 않고 기존 버전 태그와 함께 읽으며, 신규 솔로·대전 기록은 `classic-v2`로 저장한다. 버전 간 점수는 같은 난이도의 점수로 비교하지 않는다.

## 검증 기준

현재 `classic-v2`의 100ms 간격 8정답은 내부 너비 2.44, alpha 24, 점수 8이다. 이어 오타는 1/27/5, 삭제는 1/30/3, 1100ms의 다음 정답은 1.24/33/4이다. TypeScript와 Rust가 같은 수치를 만족해야 한다. 원작 `classic-v1`의 비교값은 각각 43/19/22, 1/17/15, 1/20/10, 2.5/23/11이었다.

이전 초안의 시간제·콤보·FLOW 게이지 테스트는 원작 검증이 아니므로 교체했다. 새로운 검증은 원본 수치, UI의 실제 가림, 완주, IME, 다국어 정적 HTML, 두 브라우저 대전 흐름을 다룬다.

## 다음 개선의 우선순위

원작이 기준이다. 새 난이도나 연습 모드는 Classic 기록과 분리하여 별도 승인 후 추가한다. 대전의 공정성은 지연 보정과 자동 입력 대응이 추가 연구 대상이다. 서버 판정은 클라이언트 점수 위조를 막지만 사람이 직접 입력했다는 사실까지 증명하지 못한다. 단말의 발열·통신·Android 프로세스 생존성과 실제 동시접속 부하도 운영 데이터로 검증해야 한다.
