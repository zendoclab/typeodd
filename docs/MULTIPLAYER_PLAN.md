# Typeodd 1:1

## 현재 구현

솔로와 별도로 언어별 익명 자동 매칭을 제공한다. 같은 지문, 3초 카운트다운, 원작의 마킹·흰 덮개·점수 규칙을 사용한다. Rust 서버가 먼저 완주를 확인한 쪽이 승리하며 점수는 보조 기록이다. 사용자 이름과 채팅 입력은 요구하지 않는다.

## 구조

```text
SvelteKit / Cloudflare Pages
    ↕ WSS
Cloudflare → named Tunnel → Termux loopback:8793
                              Rust Axum / Tokio
                              언어별 대기열 → 대전별 task
                              bounded channel → SQLite writer thread
```

게임 판정은 Rust 메모리에서 실행한다. SQLite 쓰기는 전용 스레드에서 처리하여 키 입력 경로의 디스크 대기를 피한다. 각 대전은 독립된 Tokio task이며 대기열만 짧게 잠근다. 서버 시각으로 입력과 감쇠를 계산하고 클라이언트가 보낸 점수는 받지 않는다. 프런트는 반응성을 위해 예측하고 순번이 확인된 서버 상태로 보정한다.

## 프로토콜

경로는 `/v1/ws`, 외부 주소는 `wss://typeodd-api.cording.ai/v1/ws`다.

| 방향 | 메시지                                            |
| ---- | ------------------------------------------------- |
| C→S  | `{type:"queue",language:"en"}`                    |
| C→S  | `{type:"input",seq:1,value:"a"}`; 삭제는 빈 value |
| C→S  | `{type:"ping"}` / `{type:"leave"}`                |
| S→C  | `queued`                                          |
| S→C  | `matched`: room, you, text, title, startsIn       |
| S→C  | `state`: players, seqs, elapsed, startsIn         |
| S→C  | `finished`: winner, reason, players, elapsed      |

입력 순번은 플레이어별로 1씩 증가한다. NFC 한 글자와 오류 삭제만 판정한다. 카운트다운 중 입력은 받지 않는다. 기록 버전은 `classic-v1`이다.

## 연결과 한계

- 10초마다 WebSocket ping, 35초 동안 응답이 없으면 연결 정리.
- 연결 종료 확인 후 10초가 지나면 상대 승리. 둘 다 종료하면 무승부. 현재 대전에는 재접속할 수 없으며 새 매칭을 시작해야 한다.
- 최대 15분 후 승자 없이 방 종료. 이는 대전 서버의 자원 한도이며 솔로에는 시간 제한이 없다.
- 동시 연결 상한 256, 연결당 초당 메시지 60개, 메시지 512바이트, bounded channels. 이는 측정된 수용 인원이나 성능 보장이 아니다.
- 정확한 Origin 목록으로 브라우저 연결을 제한한다. Origin은 인증이나 봇 방지 수단이 아니다.
- 서버 수신 시각으로 계산하므로 네트워크 지연·패킷 묶음이 수치와 접전 승패에 영향을 줄 수 있다. 상금/공식 랭킹 대회용 공정성을 보장하지 않는다.

## 데이터

SQLite WAL에 익명 대전 ID·지문·언어·양측 통계·승자·종료 사유·소요시간을 저장한다. 원시 키 입력/이름/IP는 게임 DB에 저장하지 않는다. 7일 지난 요약은 서버 시작과 다음 결과 저장 시 삭제한다. DB와 Tunnel 자격 증명은 서버에만 둔다.

## 채팅 후속 기획

채팅은 이번 1:1에 붙이지 않는다. 후속 버전에서 두 사람이 동의한 짧은 문장을 다음 비공개 대전의 지문으로 사용하는 방식을 검토한다. 보낸 사람의 사전 기억 이점이 있으므로 공개 경쟁 지문과 분리해야 한다. 메시지 보관·삭제·신고와 입력창 혼동을 먼저 설계한 뒤 구현한다.
